# 《仙农洞天：精怪工坊》开发实现路线与验收门禁

## 0. 文档定位

本文件把 GDD 转成开发执行路线，回答团队最关心的 4 个问题：

- 先做什么。
- 每个阶段做到什么程度算过。
- 哪些系统必须先验证。
- 什么时候可以进入 Demo 和发行准备。

---

## 1. 开发总路线

| 阶段 | 周期 | 目标 | 核心交付 |
|---|---:|---|---|
| P0 原型 | 0 到 8 周 | 跑通最小核心循环 | 种田、成精、精怪协助、店铺一次成交 |
| P1 垂直切片 | 9 到 20 周 | 做完前 3 小时可玩内容 | 前 3 小时、第一章、旧铺、灵渠修复 |
| P2 Demo | 21 到 32 周 | 做出对外试玩版本 | Demo QA、Steam 素材、崩溃恢复、埋点 |
| P3 Alpha | 33 到 52 周 | 全系统可玩 | 四章主线、第二年核心循环、基础平衡 |
| P4 Beta | 53 到 68 周 | 内容完整和稳定性 | 全剧情、全精怪、全店铺和秘境、性能优化 |
| P5 Release | 69 到 78 周 | 发行候选 | 平台审核、成就、云存档、本地化、商店素材 |

---

## 2. P0 原型门禁

### 必做模块

- 时间与日夜系统。
- 农田与作物成长。
- 背包与物品。
- 任务和事件触发。
- 第一只萝卜精成精。
- 精怪执行 3x3 浇水。
- 基础加工。
- 旧铺上架和顾客购买。

### 通过标准

| 验收项 | 标准 |
|---|---|
| 核心循环 | 玩家能完成种植、收获、加工、售卖、修复 |
| 成精卖点 | 30 分钟内触发萝卜精入队 |
| 自动化 | 萝卜精工作必须在场景中可见 |
| 店铺 | 至少 1 名顾客能根据商品标签购买 |
| 存档 | 能保存一天内关键状态 |

---

## 3. P1 垂直切片门禁

### 必做内容

- 前 3 小时完整体验。
- 序章到第一章主线。
- 白芷、许伯、张铁山基础事件。
- 萝卜精和第二只精怪。
- 旧铺试营业。
- 第一段灵渠修复。
- 顾客想法泡泡和日终诊断。

### 通过标准

| 验收项 | 标准 |
|---|---|
| 体验节奏 | 每 15 分钟有明显反馈 |
| 留存钩子 | 30、60、120、180 分钟关键点全部出现 |
| 玩家理解 | 测试玩家能说明作物成精、精怪协助、顾客反馈 |
| 性能 | 目标平台稳定 60 FPS 或锁定目标帧 |
| 美术 | 至少 5 个关键场景达到可截图质量 |

---

## 4. P2 Demo 门禁

### 必做内容

- 可公开试玩包。
- 开场、第一章、旧铺、精怪协助、灵渠修复。
- 至少 2 条精怪事件。
- 至少 3 种顾客类型。
- 至少 1 个轻秘境或秘境预告。
- Demo QA 清单全覆盖。

### 通过标准

| 验收项 | 标准 |
|---|---|
| 崩溃 | 2 小时试玩无阻断崩溃 |
| 卡死 | 主线和店铺流程无软锁 |
| 引导 | 新玩家无需外部说明可完成核心循环 |
| 素材 | 至少 6 张实机截图可用于 Steam |
| 反馈 | 玩家能说出至少 1 个喜欢的精怪行为 |

---

## 5. P3 Alpha 门禁

### 必做内容

- 四章主线全可玩。
- 8 位核心 NPC 关系线第一版。
- 48 精怪形态第一版。
- 店铺标签、定价、货架主题、名铺赛季。
- 秘境节气机制至少 8 个。
- 第二年目标册第一版。

### 通过标准

| 验收项 | 标准 |
|---|---|
| 主线 | 从新开档到终章可完整通关 |
| 经济 | 无明显破产锁死或无限刷钱 |
| 后期 | 通关后至少 10 小时有目标可追 |
| 内容 | 所有 CSV 关键表可导入并被运行时引用 |
| 存档 | 主线前后版本迁移不丢核心状态 |

---

## 6. P4 Beta 门禁

### 必做内容

- 全剧情和支线完整。
- 全精怪事件和动作接入。
- 所有秘境、Boss、远征、年轮试炼接入。
- 本地化覆盖计划执行。
- 音频、UI、手柄或键鼠操作优化。

### 通过标准

| 验收项 | 标准 |
|---|---|
| 完成度 | 首发范围内无占位内容 |
| QA | P0/P1 阻断问题清零 |
| 性能 | 目标机器长时间游玩稳定 |
| 体验 | 后期 UI 不压迫，目标册能指导玩家 |
| 发行 | 商店素材全部替换为实机素材 |

---

## 7. P5 Release 门禁

必须完成：

- Steam 页面素材最终版。
- 成就、云存档、语言、控制器适配确认。
- 法务、版权、音乐授权确认。
- 发行包安装、卸载、更新、崩溃日志检查。
- 首日补丁计划和社区公告。

---

## 8. 结论

开发不应从“把所有系统都做一点”开始，而应从最小核心体验开始：

> 种下作物，作物成精，精怪帮忙，商品卖出，洞天恢复。

只要这条链在 P0 和 P1 被验证，后续内容扩展才有意义。
