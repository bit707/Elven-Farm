# 《仙农洞天：精怪工坊》存档字段清单

## 0. 文档定位
这份文档用于把现有设计方案转成程序可落地的存档模型。

目标：
- 明确正式商业化版本需要持久化哪些状态
- 帮客户端程序与技术策划提前规避“后期加字段炸档”
- 给 QA 提供存档验证范围

说明：
- 本文按模块拆字段，不限定具体序列化格式
- 推荐采用“存档版本号 + 模块分块 + 向前兼容迁移”方案
- 字段命名优先对齐现有 CSV 的 ID 与 `snake_case`

---

## 1. 存档设计总原则

### 1.1 必须保存的内容
- 会影响玩法结果的长期状态
- 影响剧情、关系、章节推进的状态
- 玩家建设与资源投入结果
- 精怪、订单、店铺、天气、节气等时间推进结果

### 1.2 不建议直接保存的内容
- 可以由配置与状态重新计算出的缓存结果
- 单纯 UI 临时展开状态
- 运行期调试信息

### 1.3 推荐结构

```text
save_root
|- meta
|- world
|- player
|- inventory
|- farm
|- spirits
|- buildings
|- workshop
|- shop
|- npc
|- quests
|- events
|- exploration
|- guide
|- statistics
```

## 15. 版本兼容建议

### 15.1 必做策略
- 每个存档写入 `save_version`
- 每次大版本增加迁移器
- 删除字段时至少保留一版兼容读取

### 15.2 风险最高的模块
- `farm_tile_list`
- `spirit_instance_list`
- `quest_progress_list`
- `building_instance_list`
- `shop` 价格与货架状态

### 15.3 QA 必测场景
- 章节切换前后读档
- 节气切换当天读档
- 精怪进化瞬间读档
- 店铺营业中断档恢复
- Boss 战前后读档
- 终章建阵过程中断恢复

---

## 16. 建议落地顺序

1. 先建立 `meta`、`world`、`player`、`inventory` 基础结构
2. 再接 `farm`、`buildings`、`workshop` 三个高频生产模块
3. 接入 `quests`、`events` 保证主线不断档
4. 最后接 `shop`、`spirits`、`npc`、`exploration` 的复杂状态

这份清单的目标不是一开始把代码写死，而是让团队在正式开发前就知道“哪些状态迟早必须持久化”。
