## Steam Depot Preflight

```powershell
npm run steam:preflight
```

生成目录：

```text
dist\xiannong-dongtian-steam-depot\preflight
```

该命令不会调用 SteamCMD，也不会上传任何内容；它会读取当前 Steam depot staging，生成 `STEAM_PREFLIGHT_REPORT.md/json` 与 `STEAM_FILE_MANIFEST.json`，记录 VDF 摘要、文件数量、SHA1、Steam-ready PNG 数量、standalone/desktop-shell 是否携带，以及 AppID/DepotID、签名 `.exe`、SteamCMD preview 等仍未满足的阻塞项。正式上传前仍需使用真实 Steamworks 后台信息和 SteamCMD preview build 验证。

## 操作

1. 点击灵田格子。
2. 开局可先点主世界 `新手三步口授牌`，按 `清荒 -> 落种 -> 补水` 读懂当前入口；它只定位清荒、播种、浇水或入夜按钮，不会自动清理、播种、浇水、收获、入夜、扣体力、扣种子、推进任务或消耗资源。随后选择 `当前种子`，再 `播种`、`浇水`、`入夜结算`；结算后查看 `日终总结` 的收入、成长、风险和 `明日建议`。
3. 成熟后 `收获`，第一次收获会触发萝卜精入队。
4. 继续种植，使用 `精怪协助` 让萝卜精给 3x3 范围自动浇水；完成后先看主世界 `精怪代浇九宫格动作签`，确认萝卜精按 1-9 格跑完 `起步 -> 九格走水 -> 省力入账`，再查看 `精怪省力账留签`，确认这次浇了几格、省下多少体力、下一片待浇田在哪里。动作签和省力账只定位回看，不会再次触发协助或自动浇水。
5. 在第一只精怪入队前先查看 `精怪` 面板的 `第一只精怪倒计时`，也可以直接点主世界 `前30分钟成精承诺牌`，确认清田、播种、成精预告、手动收获和 3x3 自动浇水的下一步；当萝卜苗已经出现轻颤或探头，主世界 `第一夜成精伏笔灯` 会把第1夜轻颤、第2晨探头、成熟后手动收获和入队后的 3x3 代劳串成四段可点路线，点击只定位异常萝卜苗、收获按钮或伙伴栏，不会自动入夜、收获、触发成精或协助浇水；第一只精怪入队后、第一次 3x3 代劳前，点主世界 `第一伙伴入队三拍签`，回看 `作物转身 -> 伙伴栏亮 -> 3x3 代劳`，它只定位田块、伙伴栏和精怪协助入口，不会自动收获、触发成精、协助浇水、派工、入夜或消耗体力；第一次清荒后，主世界 `清荒露纹回响` 会把清开的地块、洞天灵息和复苏总览连起来，只定位不自动继续清理；入队后再点击 `摸摸` 或 `喂食`，观察心情、饱腹和羁绊变化，再点主世界 `伙伴记忆三拍签` 看 `名字 -> 动作 -> 短台词` 和复述提示，确认自己能说出精怪名字或刚才的行为。
6. 在 `精怪` 面板查看 `个体记忆`，当事件显示 `可触发` 时点击 `触发事件`，完成后会获得奖励并写入记忆旗标。
7. 在 `精怪` 面板查看 `精怪自动化巡演牌`，再切换农田岗、工坊岗、店铺岗或远征岗；巡演牌会同步展示六线岗位动作、收益和缺口，主世界 `精怪接力线` 会把田垄、后厂、旧铺等岗位串成接力节点。第一次让精怪完成 3x3 代浇后，如果当前已有可做配方，主世界 `精怪省力去向桥` 会把省下的体力接到 `转去入锅`、`订单/回款` 或 `旧铺备货`，点它只切到配方栏或订单板，不会自动加工、排产、交单或消耗材料。点击定位只辅助查看，接力线只定位，不自动切岗、派工、排产、开铺、发商队、处理风险、入夜或消耗资源。点击 `短途派遣` 可获得奖励并提升远征熟练。
8. 选择 `当前配方`，先点主世界后厂旁的 `工坊开锅价值牌`，查看原料裸卖、出锅基价、订单/旧铺去向和这锅为什么值得做；若主世界亮起 `原料齐火候签`，可以点它把 `原料已齐 -> 手动加工 -> 出锅去向` 定位到配方栏和加工按钮；确认后再手动用萝卜或白菜 `加工` 成菜品，再 `开铺` 售卖。排产后可在主世界点击后厂五段工序手感节点，查看备料、投料、稳火、出锅、入仓的当前状态；如果已有精怪在工坊岗，也可以点 `精怪帮火小动作`，看它正在递料、投料、压火、盛盘还是贴签，以及下一步该看伙伴栏、工坊队列还是配方栏。出锅后可点主世界 `出锅去向三联签`，同时查看这锅菜接到哪张订单、适合挂哪种旧铺货签、是否继续备货再排产；若主世界亮起 `工坊到旧铺备货桥`，再点它查看 `出锅入仓 -> 擦亮货签 -> 门口会看见`，确认这份成品如何从背包库存接到旧铺货眼、陈列诊断和开铺前顾客预判；第一张订单被香气引出后，再点 `第一单利润对照签`，看 `原料裸卖 -> 出锅增值 -> 订单回款`、`收益差条`、`订单约` 和 `多赚`，确认订单收益高于裸卖再手动去订单板交付。价值牌、原料齐火候签、工序节点、帮火小动作、三联签、工坊到旧铺备货桥和第一单利润对照签只解释流水台、定位伙伴栏/工坊队列/配方栏/加工按钮/订单/旧铺面板，不会自动切岗、排产、加工、出锅、交单、上架、开铺、接客、成交、改价、补货、入夜、扣材料、扣库存、发奖励或消耗资源。
9. 在 `洞天建设` 面板建造小仓房、磨坊或灵井；磨坊会解锁工坊设备效率，灵井会给部分田地补水。

## 素材

```powershell
npm run assets:generate
```

生成目录：

```text
assets
assets\steam-ready
```

当前素材为项目自有程序化 SVG，占位用途是让 Demo 具备可展示视觉基础；后续可以替换为手绘或 AI 生成的最终商店素材。

游戏内 `素材` 面板会先显示 `vsa_010 素材清单证据牌`，把 8 张核心循环截图、卖点覆盖数、`至少6张截图能表达卖点` 的验收状态，以及 trailer / short video 的剪辑线收在同一张卡里；短视频节奏按 `荒田开局 -> 作物成精 -> 精怪代劳 -> 加工订单 -> 旧铺成交 -> 洞天修复/秘境/终章目标` 推进，用于 Demo 素材评审，不代表已经进入正式上架阶段。

当前会额外生成 `assets\steam-ready`：

- `source-svg`：Steam 尺寸源文件，包含 Store Header 920x430、Small 462x174、Main 1232x706、Vertical 748x896、Library Capsule 600x900、Library Header 920x430、Library Hero 3840x1240 和 8 张 1920x1080 截图源图。
- `png`：同名 PNG，由 bundled Python/Pillow 渲染，供商店页布局、发行清单预审、QA 尺寸检查和 Demo 宣发占位使用。

这些 Steam-ready PNG 已具备正确尺寸和项目自有占位视觉，但仍不是最终上架素材；正式上架前应以最终可执行文件捕获的真实实机截图、正式 key art 和 PV 替换。
